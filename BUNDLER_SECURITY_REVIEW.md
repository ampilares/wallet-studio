# Bundler security review

Reviewed 8 September 2026 by Friday. Scope: the local `bundler` directory, its nested Git history, source, compiled output, configuration, stored data, and installed dependencies. Public npm metadata and package archives were checked without installing or executing downloaded packages.

**Verdict: the original repository includes a confirmed malicious dependency. The current working copy has already removed it. No active wallet drainer, private-key exfiltration path, or prompt injection instruction was found in the current first-party files, but there are remaining security risks before live use. This review does not establish whether an earlier installation compromised the computer.**

1. **High — confirmed malicious dependency in the committed version; absent from the current installation.** Commit `68268ba92f879c4fa69694129bf2c210bfb387da` declares `oscar-redis: ^5.11.2`. The preceding commit `8027caf49d79c58b22ad8cfab2427d343e8756fc` introduced `ioredis-xyz`; the later commit replaced its name with `oscar-redis`. Neither change added a Redis feature or import to the application. The committed lockfile does not contain the newly declared dependency, so ordinary installation could resolve packages beyond that lockfile.

   npm now publishes only a security holding version for `oscar-redis`. Its replacement README explicitly says the package contained malicious code and was removed by the npm security team. Registry metadata dates the holding version to 7 September 2026. This confirms a malicious package in the original dependency set; it does not identify the removed payload's exact behavior or prove it ran on this computer. Sources: [npm package](https://www.npmjs.com/package/oscar-redis), [registry metadata](https://registry.npmjs.org/oscar-redis), [replacement archive](https://registry.npmjs.org/oscar-redis/-/oscar-redis-0.0.1-security.tgz). Local evidence: [original manifest](D:/Shared/GitHub/wallet-studio/.bundler-audit/original-package.json:30), [npm removal notice](D:/Shared/GitHub/wallet-studio/.bundler-audit/npm-removal-notice.md:3).

   The existing local edits remove that dependency, pin the remaining direct dependencies, and disable install scripts in `.npmrc`. `oscar-redis`, `ioredis-xyz`, `redis-type-intel`, and `ulid-intel` are absent from the current installed tree. Preserve these changes: they are not committed in the nested repository. If the original dependencies were previously installed, investigate that environment before using valuable keys; a clean current directory does not undo past execution. If exposure is confirmed or cannot be reasonably excluded, rotate affected credentials and replace affected wallet keys from a clean environment. Changing the encryption passphrase alone cannot invalidate an exposed private key.

2. **High — current Windows permissions allow other local users to alter signing inputs.** The ACLs on `.env`, `data/wallets.json`, and `data/bundles.json` grant `Authenticated Users` Modify and `Users` ReadAndExecute. Consequently, another local account could modify a bundle's destination, calldata, amount, or mode, then wait for the owner to execute it with unlocked keys. File locks coordinate cooperating processes; they do not authenticate the stored instructions. `JsonStore` reads JSON without runtime schema validation, and the executor signs its stored target, calldata, and value. Its simulation checks whether an EVM call succeeds, not whether the transfer or approval matches the owner's intent. References: [JSON loading](D:/Shared/GitHub/wallet-studio/src/database/JsonStore.ts:25), [signing inputs](D:/Shared/GitHub/wallet-studio/src/core/ExecutionEngine.ts:179), [ACL evidence](D:/Shared/GitHub/wallet-studio/.bundler-audit/filesystem-permissions.json).

   Restrict the checkout, configuration, and active data directory to the intended account and necessary administrative identities. Before live signing, validate and decode actions, bind plans to a chain ID, and check the exact recipients, spenders, amounts, and fee limits against an approved plan. Do not treat third-party bundle JSON as safe merely because simulation succeeds. The present `.env` has an empty wallet passphrase, so this finding does not mean a passphrase was exposed by that file during this review.

3. **Medium — configured DEX contracts are trusted without verification.** Any supplied `DEX_ROUTER_ADDRESS` and `WETH_ADDRESS` are accepted. The same router provides the quote and receives ETH; a malicious compatible contract can return a plausible quote and accept the payment without delivering the promised tokens. An `eth_call` that does not revert is insufficient to establish trustworthy swap behavior. No configured malicious router was found. This is an exploitable configuration trust boundary, not evidence of an embedded drainer. References: [router registration](D:/Shared/GitHub/wallet-studio/src/core/Bundler.ts:59), [quote](D:/Shared/GitHub/wallet-studio/src/dex/UniswapV2Adapter.ts:50), [payment destination](D:/Shared/GitHub/wallet-studio/src/dex/UniswapV2Adapter.ts:116), [simulation](D:/Shared/GitHub/wallet-studio/src/simulation/Simulator.ts:117).

   Use independently verified contract addresses on the intended chain and validate code/proxy identity before allowing them to receive funds or approvals. Enforce spending and fee ceilings independently of RPC estimates and editable bundle metadata.

**What checked out in the current copy**

- All 22 installed packages matched their public npm archives: 13,268 package files, no changed, missing, or extra package files. Archive integrity values also matched the registry and lockfile. [Integrity results](D:/Shared/GitHub/wallet-studio/.bundler-audit/installed-integrity.json).
- npm's bulk advisory endpoint returned no advisories for the current lockfile. This is an advisory check, not a proof that every dependency is harmless. [Advisory response](D:/Shared/GitHub/wallet-studio/.bundler-audit/advisories.json).
- A fresh TypeScript build succeeded. All 66 JavaScript and declaration files matched the existing `dist` files byte for byte; no extra executable build files were found. The 24 existing security/concurrency tests passed, using fake transactions and temporary stores with the real `.env` disabled.
- Reviewed first-party files contained no hidden payout address, remote-code loader, secret-upload endpoint, malicious lifecycle hook, or instruction to override an assistant's rules. The hidden Unicode scan found no matching zero-width or bidirectional control characters in 174 first-party/configuration/build files. No active Git hooks were present in the repository's hooks directory.
- Private keys are generated with the dependency's cryptographic generator and encrypted using scrypt plus AES-256-GCM with random salts and IVs. Neither an empty passphrase nor the former public example decrypted any of the ten existing stored wallets. No private key was printed or exported.
- The consolidation function deliberately transfers most of a wallet's ETH, but only to its caller-supplied destination. Transfers and approvals likewise use supplied destinations and amounts; no hidden beneficiary was found. The sample Solidity contract permits its configured owner to mint unlimited tokens, which is a disclosed centralized supply control, not a secret transfer bypass. Placeholder deployment is blocked in live mode, and mock-router actions are blocked before live signing.

**Current state and limits**

The local `.env` selects `mainnet` with `simulation` mode, no wallet passphrase, and `DATA_DIR=./data/mainnet`; that configured data directory does not currently exist. The existing files under `data/` contain ten encrypted wallets and a completed mock simulation with ten actions and no recorded transaction hashes. Local records alone cannot prove no transactions occurred elsewhere.

The removed malicious payload was unavailable through its version metadata, so its installation triggers, exfiltration destinations, and exact drainer capabilities were not established. This was not a full host, browser-extension, npm-cache, or blockchain-forensics investigation. Registry matching proves that installed files match published packages; it does not independently audit every line of those packages or exclude publisher compromise. No transactions were broadcast, dependencies installed, or application/configuration files changed. Review artifacts were added under `.bundler-audit/` and in this report.
